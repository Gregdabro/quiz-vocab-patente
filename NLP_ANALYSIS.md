## Часть 0 — Что показал анализ реального датасета

Прежде чем проектировать систему — нужно понять, с чем реально имеем дело. Анализ `topic_2.json` (662 вопроса, "Segnali di pericolo") дал конкретные данные:

### Ключевые находки

**Баланс ответов:** VERO 322 / FALSO 340 — почти 50/50. Это важно: ни одна стратегия "всегда отвечать VERO" не работает.

Это фундаментальный факт: **вся тема строится вокруг 54 знаков, и к каждому знаку система задаёт ~12 вопросов с разными формулировками одного и того же смысла.**

**Структура предложений полностью предсказуема.** Топ шаблонов:

Это означает: студент, выучив 3–4 шаблона и ~20 ключевых слов, **лингвистически понимает 80% вопросов темы 2**.

## Часть 1 — NLP Pipeline

### 1.1 Предобработка текста

Для этого проекта рекомендую **лёгкий pipeline без тяжёлых моделей** на этапе MVP, с возможностью апгрейда:

```
Входной текст
     ↓
Lowercase + нормализация Unicode (NFC)
     ↓
Сохранение акцентов (è, à, ù — семантически значимы в итальянском)
     ↓
Удаление пунктуации (кроме апострофа внутри слов: dell'auto)
     ↓
Токенизация по пробелу + regex [a-zàáèéìíòóùú']+
     ↓
Лемматизация (spaCy it_core_news_sm)
     ↓
Фильтрация стоп-слов (двухуровневая — см. ниже)
     ↓
Построение частотного словаря
```

**Почему лемматизация, а не стемминг?** В итальянском сильная флексия: `strada / strade / stradale / stradali` — стеммер объединит их неверно. SpaCy лемматизирует корректно: `strade → strada`, `veloci → veloce`. Для обучения студента важно именно словарное слово.

**Акценты — не удалять.** `è` (является) vs `e` (и) — полностью разные слова. `può` — может. Удаление акцентов ломает семантику.

### 1.2 Двухуровневая система стоп-слов

| Уровень | Назначение | Примеры слов | Судьба при анализе |
|---|---|---|---|
| **L1 — Частотный фильтр** | Слова для исключения из ранжирования лексики | il, la, di, in, un, che, del, della | Не попадают в карточки, но остаются в примерах предложений |
| **L2 — Квази-стопы** | Слова высокой частоты, специфичные для экзамена | segnale, raffigurato, preannuncia | Показываются студенту **один раз как шаблон**, затем не повторяются в блоках |
| **Контентные слова** | Смысловая лексика — основа карточек | strada, velocità, barriere, curva | Полностью включаются в систему |

Слова L2 — это "скелет экзамена". `segnale raffigurato preannuncia` встречается 278 раз — это не лексика для изучения, это **шаблонная фраза, которую студент должен выучить как формулу**, один раз, в самом начале темы.

### 1.3 Метод ранжирования лексики

Рекомендую **гибридный скоринг** — не чистый TF-IDF, потому что он недооценивает слова, специфичные для конкретного знака:

```
score(word, block) = α × TF_block(word)
                   + β × TF_topic(word)  
                   + γ × sign_specificity(word)
                   + δ × false_answer_trap(word)
```

Где:
- `TF_block` — частота в конкретном блоке из 30 вопросов
- `TF_topic` — частота по всей теме (вес ниже, чтобы не доминировали универсальные слова)
- `sign_specificity` — насколько слово уникально для данного знака (IDF по знакам, не по вопросам)
- `false_answer_trap` — бонус для слов, которые встречаются преимущественно в FALSO-вопросах

Веса для MVP: α=0.4, β=0.2, γ=0.3, δ=0.1 — подбираются A/B тестом.

**Почему `sign_specificity` важен?** Слово `tram` встречается 10 раз только у знака 014.jpg. TF-IDF по вопросам даст ему средний вес, но по знакам — высокий. И правильно: студент **обязан знать `tram` перед блоком про трамваи**, но он не универсален для темы.

### 1.4 Семантическая группировка

Для MVP — **правило-основанная кластеризация** (без тяжёлых эмбеддингов):

```python
semantic_groups = {
    "движение_по_полосам": ["senso", "opposto", "unico", "doppio", "corsie", "carreggiata"],
    "скорость": ["velocità", "moderare", "rallentare", "fermarsi", "limite"],
    "ж/д переезд": ["ferroviario", "barriere", "semibarriere", "binari", "passaggio"],
    "ветер": ["vento", "laterale", "forte", "sbandamenti"],
    "геометрия_дороги": ["curva", "dosso", "deformata", "irregolare", "pavimentazione"],
}
```

Для V2 — sentence-transformers (`paraphrase-multilingual-MiniLM-L12-v2`) для автоматической кластеризации фраз. Вычисляется один раз офлайн, результат сохраняется в JSON.

**Обнаруженные семантические ловушки в теме 2:**
- `senso opposto` vs `senso unico` vs `doppio senso` — три разных знака, похожие слова → высокий риск путаницы → эта группа требует **специального режима "сравнение знаков"**
- `barriere` vs `semibarriere` — разные объекты одного переезда
- `strada deformata` vs `pavimentazione irregolare` vs `cattivo stato` — синонимы одного знака → показывают, что вопросы намеренно перефразированы

## Часть 2 — Система изучения лексики

### 2.1 Сколько слов на блок

Из анализа данных: в блоке из 30 вопросов (соответствующих ~2–3 знакам, т.к. каждый знак даёт ~12 вопросов) встречается примерно **40–60 уникальных контентных слов**. Но реально новых слов, которых студент ещё не видел — около **8–15 на блок** (остальные повторяются из предыдущих блоков).

**Рекомендация по блокам:**

| Тип учащегося | Новых слов на блок | Повторных слов | Итого карточек |
|---|---|---|---|
| Начинающий (знает 0 итальянского) | 8–10 | 5–7 | 13–17 |
| Средний (A2) | 12–15 | 3–5 | 15–20 |
| Продвинутый (B1+) | 15–20 | 2–3 | 17–23 |

Для целевой аудитории (иностранцы, изучают для экзамена) — **оптимум 10–12 новых слов плюс 5 повторных**.

**Первый "нулевой" блок для каждой темы:** перед первым блоком вопросов — отдельная сессия "скелетные фразы", где студент изучает шаблонные структуры:
- `Il segnale raffigurato preannuncia...` — изображённый знак предупреждает о...
- `In presenza del segnale raffigurato...` — при наличии изображённого знака...
- `indica / vieta / richiede / impone / invita` — как глаголы-предикаты

### 2.2 Порядок показа слов

**Алгоритм приоритизации карточек перед блоком:**

```
1. Шаблонные глаголы (preannuncia, indica, vieta, richiede) — если не изучены
2. Слова с высоким sign_specificity для знаков этого блока
3. Слова-"ловушки" (встречаются в FALSO ответах с неожиданным значением)
4. Семантически связанные пары/тройки (senso unico / doppio senso / senso opposto)
5. Общеупотребительные слова темы (strada, velocità, carreggiata)
```

### 2.3 Структура карточки

```
┌──────────────────────────────────────┐
│  [Изображение знака, если применимо] │
│                                      │
│  STRADA DEFORMATA                    │  ← итальянская фраза/слово
│  /ˈstraːda deforˈmaːta/             │  ← транскрипция (опционально V2)
│                                      │
│  "неровная дорога"                   │  ← перевод
│                                      │
│  Пример: "preannuncia un tratto di  │
│  STRADA DEFORMATA"                   │  ← пример из реального вопроса
│                                      │
│  ⚠️ Путают с: pavimentazione         │
│     irregolare (то же значение,      │  ← "ловушка" / синонимы
│     другая формулировка)            │
│                                      │
│  [Знаю]  [Сложно]  [Не знаю]        │  ← кнопки оценки
└──────────────────────────────────────┘
```

**Обязательные поля карточки:**
- Итальянское слово/фраза (выделена)
- Русский перевод
- Один пример предложения из реального вопроса экзамена
- Связанный знак (изображение), если слово привязано к конкретному знаку

**Опциональные поля (V2):**
- Произношение
- Антонимы / путаемые слова
- Мнемоника

### 2.4 Интервальное повторение

Для MVP — **адаптированный алгоритм Leitner с 4 ящиками**, реализованный на localStorage:

```
Ящик 0 (новые):      показывать сразу и в следующей сессии
Ящик 1 (видел):      показывать через 1 сессию
Ящик 2 (знаю):       показывать через 3 сессии  
Ящик 3 (уверен):     показывать через 7 сессий
Ящик 4 (освоено):    показывать только как review раз в 30 сессий
```

**Почему не FSRS/Anki-алгоритм для MVP?** FSRS требует хранения дат, времён, параметров стабильности и retrievability для каждой карточки. Это оверинжиниринг для одного пользователя на localStorage. Leitner-4 реализуется в 50 строках и даёт 80% эффективности FSRS.

Для Phase 2 (backend) — переходить на FSRS, он превосходит SM-2 (алгоритм Anki) на ~15% по retention.

## Часть 3 — Движок генерации блоков

### 3.1 Стратегия: знак как атомарная единица, не вопрос

Ключевое открытие из данных: **естественная единица группировки — знак (изображение), а не вопрос**. 

Алгоритм генерации блока:
```
1. Для каждого знака в теме: list(questions_per_sign)
2. Отсортировать знаки по vocab_similarity (пересечение словарей)
3. Жадно выбрать знаки пока блок не достигнет 30 вопросов:
   - Выбрать следующий знак с максимальным overlap_score с уже выбранными
   - overlap_score = |vocab(candidate) ∩ vocab(current_block)| / |vocab(candidate)|
4. Равномерно взять вопросы из каждого выбранного знака (не все 28, а пропорционально)
```

**Блок из 30 вопросов = 2–3 знака × ~10–15 вопросов каждый**. Это идеально: студент видит один и тот же знак с разных сторон (preannuncia / indica / vieta / può essere associato), закрепляет паттерны.

### 3.2 Формула оценки словарного перекрытия

```
overlap_coefficient(A, B) = |vocab(A) ∩ vocab(B)| / min(|vocab(A)|, |vocab(B)|)
```

Целевое значение внутри блока: ≥ 0.4 (40% лексики повторяется между вопросами блока).

### 3.3 Прогрессия сложности между блоками

**Порядок блоков внутри темы** определяется не номером знака в официальном списке, а лексической близостью к уже изученному:

```
Блок 1: знаки с самой простой и частой лексикой (strada, velocità, pericolo)
Блок 2: знаки, лексика которых максимально пересекается с блоком 1
...
Блок N: знаки с самой специфической лексикой (ferroviario, semibarriere)
```

Это реализуется через **граф знаков**, где вес рёбер = overlap_coefficient. Обход графа в ширину от "самого простого" знака (наибольшее кол-во общих слов с базовым словарём темы) даёт оптимальный порядок.

## Часть 5 — Учебный флоу (UX)

### 5.1 Структура сессии (новый UX поверх существующего)

**Текущий флоу (существует):**
```
HomePage → QuizPage (30 случайных вопросов) → ResultScreen
```

**Новый флоу (Этап 3 — Словарь + блочное обучение):**
```
HomePage
  ↓
TopicDetailPage (выбор темы)
  ↓
[Если первый раз] → VocabPhase (изучить 10–12 слов)
  ↓                  [Знаю] / [Сложно] / [Не знаю]
[Если уже знаком] → Пропустить vocab или быстрый review
  ↓
BlockQuizPage (30 вопросов конкретного блока)
  ↓
ResultScreen + какие слова нужно повторить
  ↓
[Если ≥ 80%] → Разблокировать следующий блок
[Если < 80%] → Предложить повторить ошибки или vocab
```

### 5.2 Психология обучения

**Главные когнитивные принципы для этого проекта:**

**1. Паттерн-распознавание, не перевод.** Цель студента — не свободно читать по-итальянски, а **распознавать знакомые шаблоны и ключевые слова**. Мозг делает это автоматически после ~15 экспозиций к шаблону. Поэтому тема 2 с её 138 повторениями `In presenza del segnale raffigurato` — это не недостаток датасета, это **обучающий актив**: после 20 вопросов студент уже не читает начало предложения.

**2. Interleaving (чередование).** Внутри блока перемешивать вопросы по разным знакам (не 28 вопросов знака 001, затем 24 знака 002). Исследования показывают: чередование снижает скорость изучения, но увеличивает долгосрочное удержание на 40%.

**3. Errorful generation.** Показывать итальянское слово и просить студента вспомнить перевод **до** того, как показать ответ — даже если он ошибётся, это лучше для памяти, чем пассивное чтение. Реализуется в карточке: итальянское слово показывается, перевод скрыт под кнопкой "Показать".

**4. Контекстная привязка.** Каждое слово должно быть прочно связано с изображением знака. `barriere` должно вызывать образ шлагбаума, не абстрактный перевод "барьеры". Поэтому в карточках обязательно изображение знака.

**5. Микро-прогресс.** "5 из 10 слов изучено" работает лучше, чем "Прогресс: 50%". Маленькие пошаговые достижения поддерживают мотивацию. В интерфейсе — показывать кружки слов (закрашенные/незакрашенные), аналогично уже существующей QuizPagination.

**Что вызывает перегрузку → как избежать:**
- Показывать все 662 вопроса сразу → **блочная структура решает**
- Незнакомый алфавит слов → **шаблонный блок в начале каждой темы**
- Одновременно учить слова И проходить тест → **строго разделить фазы**
- Скучные повторения одного и того же → **разнообразие формата карточек** (слово→перевод, перевод→слово, слово→знак)

## Часть 6 — Критический анализ и улучшения

### 6.1 Слабые стороны оригинальной идеи

**Риск 1: Vocabulary-first может замедлить начало.** Студент хочет начать практику сразу, но его заставляют учить 10 слов. Решение: первый блок темы — сразу квиз, без vocab-фазы. Слова вводятся интерактивно: при ошибке → показать ключевое слово из вопроса.

**Риск 2: Слова учатся изолированно.** Студент знает `deformata` = "деформированная", но не узнаёт в контексте `strada con pavimentazione irregolare`. Решение: в карточках всегда показывать **несколько синонимичных формулировок** (это и есть "экзаменационные ловушки").

**Риск 3: 54 знака в теме 2 — не все равно важны.** Знаки с 28 вопросами (014.jpg — трамвай) важнее знаков с 5 вопросами. Система должна **пропорционально взвешивать время** на изучение. Если знак встречается в 5% вопросов темы — студент должен потратить ~5% времени на него.

**Риск 4: Разные темы — разная структура.** Тема 2 ("Segnali di pericolo") очень однородна (все вопросы про знаки). Тема 1 ("Strada, veicoli, doveri conducente") — гетерогенна. Алгоритм генерации блоков должен быть адаптивным, не универсальным.

### 6.2 Скрытые возможности

**"Exam traps" mode.** Из данных видно: многие FALSO-вопросы используют слова-синонимы реального знака, но с неверным утверждением. Например: `"preannuncia una strada in cattivo stato"` (VERO) vs `"preannuncia una strada con ghiaia"` (FALSO — ghiaia это следствие, не то что описывает знак). Создать отдельный режим: **"Ловушки экзамена"** — показывать только пары похожих вопросов с противоположными ответами.

**Image-first learning.** Показывать изображение знака → студент называет/угадывает что он означает → открывается список ключевых слов. Это reverse flashcard и это мощнее текстовых карточек для traffic signs.

**Cross-topic vocabulary.** Слова `velocità`, `strada`, `veicoli`, `pericolo` встречаются во многих темах. После изучения темы 2 студент входит в тему 4 уже со значительным словарным запасом. Система должна это учитывать и **не показывать карточки для уже освоенных слов**.

**Contradiction detection.** Поскольку данные содержат и `text`, и `answer`, можно автоматически найти пары вопросов с похожим текстом (cosine similarity > 0.85) но разными ответами — это главные экзаменационные ловушки. Флажок `trap: true` в vocab.json — показывать их в специальном режиме.
